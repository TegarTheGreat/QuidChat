# QuidChat

[English](../../README.md) · [Bahasa Indonesia](README.id.md) · [Bahasa Melayu](README.ms.md) · [中文](README.zh.md) · [हिन्दी](README.hi.md) · [Español](README.es.md) · [Português](README.pt.md) · [Русский](README.ru.md) · **日本語** · [한국어](README.ko.md)

**あなたの**商品やサービスについて、お客様が尋ねられるチャットアシスタント — そして決して作り話をしません。

あなたの商売について述べることはすべて、あなたが渡した文書から来ていて、どの文書かも示します。根拠がないときは、推測せずにそう言います。

`<script>` タグひとつでサイトに載ります。WhatsApp、Telegram、Discord、Slack、LINE も同じ中核を使います。

> このページには、QuidChat を動かして運用するのに必要なことが揃っています。もっと深い部分 — テナント間の分離の仕組み、検索の組み立て方、保存先の選び方 — は[英語版 README](../../README.md) にあり、そちらが完全な参照です。

## はじめかた

```bash
pnpm install
pnpm build

export OPENAI_API_KEY=sk-...

# 事業者をひとつ作り、ウィジェットを置くサイトを許可する
node packages/cli/dist/main.mjs init watashi-no-mise \
  --name "わたしの店" \
  --origin https://mise.example

# 答える材料を与える
cat policy.txt | node packages/cli/dist/main.mjs add-text watashi-no-mise \
  --title "店舗ポリシー" --stdin

# すでにあるページを指してもよい
node packages/cli/dist/main.mjs add-url watashi-no-mise https://mise.example/haisou \
  --title "配送について"

# サイト全体を読ませることもできる — 管理画面の「ナレッジ」からも可能
node packages/cli/dist/main.mjs add-site watashi-no-mise https://mise.example --max-pages 25

node packages/cli/dist/main.mjs serve
```

管理画面は **http://localhost:3210/panel** にあります。設定はすべてそこにあり、上でフラグとして渡したものも含まれます。管理画面は十の言語に対応し、ブラウザの言語で開きます。それは管理画面の言語であり、お客様が読む言語とは別です。後者は「設定 → ウィジェット」で事業者ごとに決めます。

そのうえで、許可したサイトにこれを貼ります:

```html
<script src="http://localhost:3210/quidchat.js"
        data-quidchat-tenant="watashi-no-mise"
        defer></script>
```

文書に載っていることを尋ねると、答えは文書名と一緒に返ってきます。

## 答えを信用できる理由

モデルがあなたの商売について記憶から答えることはありません。あなたの店に関する事実を述べる文はすべて、アップロードした文書の一部を指していなければならず、指せなければその答えはお客様に届く前に却下され、アシスタントは「それはまだ分かりません」と伝えます。

リスクの高い話題 — 価格、割引、保証、返金、法的条件、在庫 — は推論では答えません。文書にはっきり書かれていることだけです。

断られた質問は**未回答の質問**画面に集まります。そこでお客様の言葉のままの質問を読み、答えを一度書けば、次に同じことを尋ねたお客様はそれを受け取れます。

## 知識を与える

方法は四つ。すべて管理画面の**ナレッジ**にあります。

- **テキストを貼る** — いちばん速い。店舗ポリシー、価格表、営業時間。
- **ウェブページ 1 枚** — 一度読み込み、ページが変わればいつでも読み直せます。
- **サイト全体** — 起点のアドレスからリンクをたどり、`robots.txt` を守り、一度に最大 25 ページ。各ページがそれぞれのタイトルで独立した情報源になるので、お客様が見る出典は「配送について」となり、サイト名にはなりません。
- **PDF ファイル** — 9 MB 程度まで。スキャンした PDF は理由とともに拒否されます。文字が画像なので、まず OCR が必要です。

## チャネル

サイトのウィジェットはそのまま動きます。ほかは任意です — 認証情報がなければ webhook のアドレスは `404` を返します。ウィジェットしか使わない事業者のサーバーに、認証のない WhatsApp の入口が開いているべきではないからです。

プラットフォームを `POST /v1/channels/:channel/:tenantSlug` に向けてください。

| チャネル | 必要なもの |
|---|---|
| Telegram | bot token、webhook secret |
| WhatsApp Cloud | phone number id、access token、app secret |
| WAHA（自前の WhatsApp） | WAHA のアドレス、セッション名、API key |
| Discord | bot token、public key |
| Slack | bot token、signing secret |
| LINE | channel access token、channel secret |

認証情報は管理画面の**チャネル**に入れます。すべて `QUIDCHAT_SECRET_KEY`（`openssl rand -base64 32`）で AES-256-GCM により暗号化され、管理画面は保存した値を伏せ字でも表示し返しません。

webhook secret も設定してください。署名の検証は解析や保存より先に行われるので、偽装されたリクエストは処理に届きません。これがないと、アドレスを知った人が誰でもあなたの会話履歴に言葉を差し込み、予算を使えてしまいます。

チャネルは認証情報を消さずに**一時停止**でき、その一時停止は表示だけでなく実際に応答を止めます。

## 費用を抑える

`monthly_budget_cents` は厳格な上限です。達すると、請求を積み上げ続けるのではなく、アシスタントが応答をやめます。ゼロは「上限なし」であって「支出ゼロ」ではありません。

回答モードが費用を決めます。

- **static** — 承認済みの定型回答のみ。モデルを一度も呼ばないので、運用は無料です。
- **thrifty** — あなたの文書を検索し、そこから答えます。
- **full** — 先に質問を書き換えてから検索します。見つかる量は増え、費用も増えます。

Ollama を使えば自分のマシンで動くモデルも使えます。鍵もアカウントも不要で、データはサーバーの外に出ません。同じサーバーでモデルがすでに動いていれば、管理画面がそれを見つけて勧めます。

## セキュリティ

- **テナント間の分離**はデータベースの row-level security で、アプリ側のフィルタではありません。
- **許可したサイト**が、誰があなたのウィジェットを開けるかを決めます。一覧にないサイトは拒否され、これが他人にあなたのアシスタントを埋め込まれて予算を使われることを防いでいます。
- **管理トークン**は一定時間で比較され、失敗した推測は送信元ごとに制限されます。
- **管理画面**は他サイトのフレーム内に表示されることを拒み、自分のスクリプトだけを実行します（`script-src 'self'`）。トークンがそこにあるからです。
- **認証情報**は表示し返されることも、平文で保存されることもありません。

## 保存とバックアップ

`retention_days` は期限を過ぎた会話を削除します。サーバーは起動時と一日一回それを行い、`quidchat prune` は一度実行して終了します。自分の cron に置きたい人向けです。

お客様から今日データを消してほしいと言われたときは、**会話**画面の記録削除を使ってください。メッセージ、アシスタントが示した出典、そこから生まれた未回答の記録まで一緒に消えます。

`quidchat backup` はすべてをひとつのファイルに書き出します。文書、あなたが承認した回答、そしてお客様との会話すべてです。ディレクトリをコピーするのではなく、動いているデータベースエンジンを通して取り出します。Postgres が開いているファイルをコピーすることこそ、必要になった日に復元できないバックアップができる原因だからです。マネージドな Postgres では、実行すべき `pg_dump` の行を表示します。

## 設定

| 変数 | 既定値 | 意味 |
|---|---|---|
| `PORT` | `3210` | `0` は空きポートを OS に任せる |
| `DATABASE_URL` | — | マネージド Postgres。無ければ内蔵の PGlite |
| `QUIDCHAT_DATA_DIR` | `./.quidchat/data` | PGlite の保存先。`memory` で保存しない |
| `QUIDCHAT_ADMIN_TOKEN` | — | 管理 API に必須。無ければ管理系の経路はすべて拒否 |
| `QUIDCHAT_SECRET_KEY` | — | 32 バイト、base64 か hex。管理画面で保存した認証情報を暗号化 |
| `QUIDCHAT_LOG` | `text` | リクエストごとに 1 行。ログを解析するなら `json`、不要なら `off` |

残りは管理画面で設定します。モデル、回答モード、予算、保存期間、リスクの高い話題、許可するサイト、ウィジェットの見た目。
