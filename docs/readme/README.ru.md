# QuidChat

[English](../../README.md) · [Bahasa Indonesia](README.id.md) · [Bahasa Melayu](README.ms.md) · [中文](README.zh.md) · [हिन्दी](README.hi.md) · [Español](README.es.md) · [Português](README.pt.md) · **Русский** · [日本語](README.ja.md) · [한국어](README.ko.md)

Чат-ассистент, у которого клиенты спрашивают о **ваших** товарах и услугах — и который никогда ничего не выдумывает.

Каждое его утверждение о вашем деле взято из документа, который вы ему дали, и он показывает, из какого. Когда источника нет, он так и говорит, а не гадает.

Ставится на сайт одним тегом `<script>`. WhatsApp, Telegram, Discord, Slack и LINE работают на том же ядре.

> На этой странице есть всё, что нужно, чтобы запустить QuidChat и управлять им. Более глубокие темы — как устроена изоляция между компаниями, как собран поиск, почему хранилище именно такое — в [английском README](../../README.md), который служит полным справочником.

## Быстрый старт

```bash
pnpm install
pnpm build

export OPENAI_API_KEY=sk-...

# Создайте компанию и разрешите сайт, где будет жить виджет
node packages/cli/dist/main.mjs init moy-magazin \
  --name "Мой магазин" \
  --origin https://moymagazin.example

# Дайте ему то, по чему отвечать
cat pravila.txt | node packages/cli/dist/main.mjs add-text moy-magazin \
  --title "Правила магазина" --stdin

# Или укажите на страницу, которая у вас уже есть
node packages/cli/dist/main.mjs add-url moy-magazin https://moymagazin.example/dostavka \
  --title "Условия доставки"

# Или прочитайте весь сайт — это же есть в панели, в разделе «Знания»
node packages/cli/dist/main.mjs add-site moy-magazin https://moymagazin.example --max-pages 25

node packages/cli/dist/main.mjs serve
```

Панель — на **http://localhost:3210/panel**; там живут все настройки, включая те, что выше переданы флагами. Панель говорит на десяти языках и открывается на том, который просит браузер. Это язык панели: язык, который читают ваши клиенты, задаётся отдельно для каждой компании в «Настройки → Виджет».

Затем вставьте это на сайт, который вы разрешили:

```html
<script src="http://localhost:3210/quidchat.js"
        data-quidchat-tenant="moy-magazin"
        defer></script>
```

Спросите то, что есть в ваших документах, и ответ придёт вместе с названием документа.

## Почему его ответам можно верить

Модель никогда не отвечает по памяти о вашем деле. Любая фраза, утверждающая факт о вашем магазине, обязана указывать на фрагмент загруженного вами документа; если не может — ответ отклоняется, не доходя до клиента, и ассистент говорит, что этого он пока не знает.

Темы повышенного риска — цены, скидки, гарантия, возвраты, юридические условия, наличие — никогда не выводятся логикой. Только то, что прямо написано в ваших документах.

Отклонённые вопросы попадают на экран **«Без ответа»**. Там вы читаете вопрос клиента его словами и пишете ответ один раз; следующий, кто спросит о том же, получит его сразу.

## Как дать знания

Четыре способа, все в разделе **«Знания»** панели:

- **Вставить текст** — самое быстрое. Правила, прайс, часы работы.
- **Одна страница** — читается один раз и перечитывается, когда вы её измените.
- **Весь сайт** — обходит ссылки от стартового адреса, соблюдает `robots.txt`, до 25 страниц за проход. Каждая страница становится отдельным источником со своим заголовком, чтобы ссылка, которую видит клиент, гласила «Условия доставки», а не название сайта.
- **Файл PDF** — примерно до 9 МБ. Отсканированный PDF отклоняется с объяснением: его буквы — картинки, и сначала нужен OCR.

## Каналы

Виджет для сайта работает сразу. Остальное — по желанию: без учётных данных адрес вебхука отвечает `404`, потому что у компании, которой нужен только виджет, не должно быть открытой точки WhatsApp на сервере.

Направьте платформу на `POST /v1/channels/:channel/:tenantSlug`.

| Канал | Что нужно |
|---|---|
| Telegram | токен бота, секрет вебхука |
| WhatsApp Cloud | phone number id, access token, app secret |
| WAHA (свой WhatsApp) | адрес WAHA, имя сессии, API key |
| Discord | bot token, public key |
| Slack | bot token, signing secret |
| LINE | channel access token, channel secret |

Учётные данные вводятся в разделе **«Каналы»**. Всё шифруется ключом `QUIDCHAT_SECRET_KEY` (`openssl rand -base64 32`) алгоритмом AES-256-GCM, и панель никогда не показывает сохранённое значение обратно — даже в замаскированном виде.

Задайте и секрет вебхука. Подпись проверяется до того, как что-либо разобрано или сохранено, поэтому поддельный запрос не доходит до обработки — без него любой, кто узнает адрес, сможет вписывать слова в вашу историю диалогов и тратить ваш бюджет.

Канал можно **поставить на паузу**, не удаляя учётные данные, и пауза действительно останавливает ответы, а не просто меняет надпись.

## Контроль расходов

`monthly_budget_cents` — жёсткий предел: по достижении ассистент перестаёт отвечать, а не продолжает набирать счёт. Ноль означает «без предела», а не «ноль расходов».

Режим ответа определяет стоимость:

- **static** — только одобренные готовые ответы. Модель не вызывается вовсе, поэтому работа бесплатна.
- **thrifty** — ищет в ваших документах и отвечает по ним.
- **full** — сначала переписывает вопрос, потом ищет. Находит больше и стоит дороже.

Можно использовать модель на своей машине через Ollama: ни ключа, ни аккаунта, и ничего не покидает ваш сервер. Если QuidChat заметит уже запущенную модель на том же сервере, панель сама предложит её.

## Безопасность

- **Изоляция компаний** — row-level security в базе, а не фильтры в коде приложения.
- **Разрешённые сайты** решают, кто может открыть ваш виджет. Сайт не из списка получает отказ — именно это не даёт постороннему встроить вашего ассистента к себе и потратить ваш бюджет.
- **Токен администратора** сравнивается за постоянное время, а неверные попытки ограничиваются по источнику.
- **Панель** отказывается открываться внутри чужого фрейма и выполняет только свои скрипты (`script-src 'self'`), потому что токен хранится именно там.
- **Учётные данные** никогда не показываются обратно и никогда не хранятся открытым текстом.

## Хранение и резервные копии

`retention_days` удаляет диалоги старше указанного срока. Сервер делает проход при запуске и раз в сутки; `quidchat prune` выполняет то же один раз и завершается — для тех, кому удобнее видеть это в своём cron.

Если клиент просит удалить его данные сегодня, воспользуйтесь удалением переписки на экране **«Диалоги»**: уйдут все сообщения, указанные источники и записи о вопросах без ответа из этого диалога.

`quidchat backup` записывает всё в один файл: документы, одобренные вами ответы и каждый клиентский диалог. Копия снимается через работающий движок базы, а не копированием каталога — копировать файлы, открытые Postgres, это и есть способ получить резервную копию, которая не восстановится именно тогда, когда понадобится. На управляемом Postgres команда печатает строку `pg_dump`, которую нужно выполнить.

## Настройки

| Переменная | По умолчанию | Значение |
|---|---|---|
| `PORT` | `3210` | `0` — попросить у системы свободный порт |
| `DATABASE_URL` | — | Управляемый Postgres. Без неё используется встроенный PGlite |
| `QUIDCHAT_DATA_DIR` | `./.quidchat/data` | Где PGlite хранит данные. `memory` — не сохранять |
| `QUIDCHAT_ADMIN_TOKEN` | — | Обязателен для админского API; без него все админские маршруты отказывают |
| `QUIDCHAT_SECRET_KEY` | — | 32 байта, base64 или hex. Шифрует учётные данные, сохранённые в панели |
| `QUIDCHAT_LOG` | `text` | По строке на запрос. `json` — для разбора логов, `off` — без логов |

Остальное настраивается в панели: модели, режим ответа, бюджет, срок хранения, темы риска, разрешённые сайты и внешний вид виджета.
